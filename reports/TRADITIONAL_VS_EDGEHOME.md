# 传统固定场景与 EdgeHome 动态规划对比

本报告公平采用一个传统固定观影场景作为基线：关闭窗帘、主灯 20%、打开电视、空调制冷并设为 25℃。该基线适合固定需求，但不会读取本轮状态与临时约束。

| 指标 | EdgeHome | 传统固定观影场景 |
| --- | ---: | ---: |
| 用户约束违反次数 | 0 | 3 |
| 错误房间控制次数 | 0 | 5 |
| 不必要控制次数 | 0 | 3 |

| 用例 | EdgeHome 结论 | 传统固定场景结论 |
| --- | --- | --- |
| A：白天高光照高温 | 满足本用例的目标、状态与约束要求 | 固定场景在该环境下没有明显冲突 |
| B：夜晚低温 | 满足本用例的目标、状态与约束要求 | 低温环境仍会启动并设置空调；窗帘已关闭时仍重复关闭 |
| C：用户明确不要空调 | 满足本用例的目标、状态与约束要求 | 固定观影场景仍会打开/设置空调 |
| D：主灯不低于 40% | 满足本用例的目标、状态与约束要求 | 固定观影场景主灯 20% 低于用户亮度下限 |
| E：卧室观影且客厅不要动 | 满足本用例的目标、状态与约束要求 | 固定观影场景只控制客厅设备 |
| F：空调不低于 25℃ | 满足本用例的目标、状态与约束要求 | 固定场景在该环境下没有明显冲突 |

结论：传统固定场景执行速度和行为稳定，适合固定需求；EdgeHome 规划成本更高，但可以处理家庭状态、临时约束和房间边界。报告不宣称传统智能家居无用，也不把 dry-run 规划证据替代实时 MQTT 验收。
