# SpaceButler 视频演示方案

## 一、视频要讲清楚什么

推荐录制一条 **4 分钟主片**，用“准备在客厅看电影”贯穿四项能力：

1. 不同品牌设备被统一发现、纳管和控制；
2. 用户用语音表达自然语言目标；
3. AI 观察实时环境，生成候选计划，经过策略校验后执行并回读；
4. 多设备动作可沉淀为可审阅、可调整、可重复执行的工作流。

核心信息不是“界面漂亮”，而是：

> 设备和动作来自 Home Assistant 实时清单；AI 负责理解、规划和选择；执行结果以设备状态回读为准。

演示链路：

```text
麦克风 → 豆包流式 ASR → LangGraph Agent → 候选计划/预测
                                      ↓
                                Policy Guard
                                      ↓
品牌适配器 → Home Assistant → ESPHome 设备 → 状态回读与验证
                                      ↓
                             可保存的多设备工作流
```

## 二、当前录制基线

2026-09-01 本机现场检查结果：

- 工作台、Home Assistant、本地规划模型和 Agent 运行时正常；
- 10/10 台 ESPHome 设备在线，实体绑定无缺失；
- 豆包流式语音服务已配置；
- 5 个品牌生态已映射：小米米家、Aqara、美的、鸿蒙智联、Philips Hue；
- 当前没有已保存工作流，正式录制前需要创建一个演示工作流；
- 当前规划为本地模型单通道。推理等待较长时可以剪辑压缩，但必须保留“正在规划”和最终结果，不能伪装成即时返回。

### 当前必须注意的未完成项

工作流后端已经提供服务端持久化和对话触发接口，但当前前端仍把工作流保存在
`localStorage`，并在工作流页面内逐步调用设备控制接口。因此：

- **当前可稳定录制**：工作流页面内生成、保存、口令匹配、执行和状态回读；
- **暂不作为正式镜头**：在 AI 管家里用语音触发刚刚由前端保存的工作流；
- 完成前后端工作流存储统一后，再把“语音语义匹配 → 确认 → 执行工作流”加入主片。

## 四、开拍前操作

### 1. 启动并自检

```powershell
Set-Location KDXF_SpaceButler
python scripts\run_workbench.py --port 8765
```

打开 <http://127.0.0.1:8765>，进入“演示控制台”：

1. 点击“就绪自检”，7 项全部通过；
2. 点击“一键重置”，等待 11 个真实复位步骤全部完成；
3. 在 AI 管家长按 V 做一次 3 秒真人语音测试，必须看到实时字幕和最终文本；
4. 用文字先跑一次观影指令预热本地模型，然后再次一键重置；
5. 删除浏览器里遗留的演示工作流，避免口令撞名。

`configured: true` 只代表语音凭据已读取，不代表麦克风、网络和上游识别已经完成现场验收，
因此第 3 步不能省略。

### 2. 预置品牌纳管镜头

为了在镜头里真正展示“接入设备”，而不只是展示现有徽标：

1. 点击“恢复出厂映射”；
2. 在“当前归属”中释放 **卧室阅读灯**；
3. 正式录制时选择 Philips Hue 并点击“扫描设备”；
4. 只勾选卧室阅读灯，确认候选设备在线且显示 Hue 原生命令预览；
5. 点击“纳管所选设备”；
6. 回到首页或空间设备页，确认其品牌徽标已变为 Philips Hue。

释放和纳管只改变品牌归属与报文翻译，不会删除 Home Assistant 实体。

### 3. 录制起始设备状态

一键重置后的标准状态应为：

- 客厅温度 30.2°C；
- 客厅主灯开启，亮度 80%；
- 客厅窗帘全开；
- 客厅空调关闭；
- 客厅电视开启；
- 客厅窗户打开；
- 卧室阅读灯关闭、照度 8 lx、无人。

这个状态给“有点热、灯别太亮”的观影目标留下真实可执行空间。

## 五、固定台词与输入

### 语音主指令

> 我准备在客厅看会电影，有点热，灯别太亮。

不要口播“它一定执行三步”。动作数量必须由当前实时状态和模型规划决定。

### 二次观察

> 现在适合看电影了吗？

期望结果是零动作，或只处理仍未满足的约束；不能把固定答案写进旁白。

### 工作流生成

> 创建观影结束流程：关闭客厅电视、关闭客厅主灯、关闭客厅空调，打开客厅窗帘。

生成后填写：

- 名称：`观影结束`
- 启动口令：`电影看完了`
- 可选别名：`电影结束了`、`帮我收尾`
- 延迟：全部设为 0，避免录制等待

## 六、剪辑与画面建议

- 分辨率 1920×1080，浏览器缩放 90%–100%；
- 每次切换页面后停 1 秒，每次关键结果出现后停 2 秒；
- 本地模型等待可压缩，但加字幕“本地模型真实推理，等待段已加速”；
- 语音段保留波形、实时字幕和松开提交三个状态；
- AI 段给候选计划、Policy Guard 和回读验证各一个近景；
- 工作流段使用左右分屏：左侧执行时间线，右侧设备实时状态；
- 屏幕字幕统一使用：`实时设备清单`、`模型候选计划`、`策略校验`、`HA 状态回读`；
- 不展示 API Key、Home Assistant Token、终端环境变量或浏览器开发者工具。

## 七、失败时怎么处理

| 现场问题 | 处理原则 |
|---|---|
| 语音无字幕或识别错 | 停止录制，重新做真人语音验收；不要改用文字后仍声称是语音输入 |
| 本地模型等待过长 | 保留开始和结果，剪掉中间等待并明确标注加速；不要换成固定返回 |
| 设备离线或实体缺失 | 回演示控制台修复，7 项未全绿不录 |
| 规划动作数与预想不同 | 按实时结果讲解，不说死动作数量 |
| 某一步执行失败 | 可以保留为“可观测失败”加分镜头；若主片需要顺畅，再修复后重录 |
| 品牌扫描没有可纳管设备 | 说明预置释放未完成，先释放卧室阅读灯再扫描 |

## 八、边界声明

- 当前设备是 ESPHome `host` 平台虚拟节点，经 Home Assistant 形成真实可控制、可回读的本地链路；
- 品牌适配器展示的是能力映射、协议字段和数值换算，不代表已经调用小米、Aqara、美的、鸿蒙或 Hue 的真实厂商云/网关；
- 语音音频会发送到豆包流式语音识别服务，本地不保存录音；
- 工作流动作和设备选择必须来自 `/api/devices` 的实时能力描述，不能在视频里宣称不存在的设备能力；
- 模型不可用时系统会安全拒绝执行，不能把确定性脚本伪装成 AI 规划。

## 九、90 秒精简版

1. 0–10 秒：首页 10/10 在线和 5 个品牌徽标；
2. 10–25 秒：Hue 扫描并纳管卧室阅读灯；
3. 25–55 秒：长按 V 说观影目标，快速展示字幕、候选计划和状态回读；
4. 55–80 秒：打开预先保存的“观影结束”工作流并执行，时间线逐项完成；
5. 80–90 秒：首页最终状态与一句总结。

90 秒版的工作流应在开拍前保存好，不在镜头里等待模型生成。
