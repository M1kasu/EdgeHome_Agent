# EdgeHome M1.5：结构化会话记忆

EdgeHome 不会把完整聊天记录无限拼接到模型提示词中。它只保存有限、强类型、可过期的会话状态，用于处理“它”“再暗一点”“也是一样”和受控的待澄清请求。

## 会话隔离

状态键由以下信息计算：

- Home Assistant `conversation_id`；
- 当前 `assistant_id`；
- 可获得时的 Home Assistant `user_id`。

下一轮必须把上一轮响应中的 `conversation_id` 传回。没有该 ID 的请求被视为新的独立会话，系统会澄清而不是继承其他会话的设备。这也意味着开发者工具中的一次性调用不能作为多轮记忆验收入口。

## 持久化与隐私

默认数据库为 `deployment/runtime/edgehome_context.db`，容器内路径为 `/runtime/edgehome_context.db`。使用 SQLite 参数化 SQL，默认 TTL 为 30 分钟，并在读取和清理时删除过期记录。

保存字段包括最近成功的房间、实体、设备类型、动作、参数、当前目标、待澄清项、待执行计划和最多 5 条结构化执行结果。不会保存访问令牌、密码、账户信息、模型密钥、原始模型输出或无限聊天记录。

## 写入规则

只有固定计划执行成功，并且 Home Assistant 已完成状态回读验证时，才会更新最近成功的实体、动作和参数。失败操作只追加失败审计结果，不会覆盖上一条成功上下文，因此后续“把它调到 30%”不会把失败目标误认为已完成。

## 支持的承接

- “它 / 这个 / 刚才那个”：仅指向同一会话内最近成功且仍存在的唯一实体；
- “卧室的也一样”：继承动作和槽位，但仅在目标设备唯一且同域兼容时执行；
- “再亮一点 / 再暗一点 / 关掉吧”：先读取当前 Home Assistant 实际状态再生成固定计划；
- 待澄清回复：数值可补充到原始请求；“对”只有在没有缺失槽位且存在候选实体时才能恢复，否则继续澄清。

设备类型冲突、实体不存在、会话过期、多候选和失败操作均不会猜测或跨会话继承。
