# 故障应急预案

## 通用原则

先说明当前故障，再展示健康检查、日志或数据证据；不临时切换云端模型，不改写结果，不把预录片段说成实时。每次恢复后先运行 `reset_demo` 和 `healthcheck`。

| 故障 | 立即处置 | 可演示的证据 / 降级 | 禁止做法 |
| --- | --- | --- | --- |
| 模型服务无法启动 | `scripts/start_demo.ps1` 后执行健康检查；确认模型路径与 8080 端口 | 简单任务快速路径、已注册模板降级、同环境预录模型片段 | 切换未声明的云模型 |
| Home Assistant 无法访问 | 检查 8123、`docker compose ps`，必要时重启 HA；再做配置检查 | 终端 HTTP、容器日志、预录状态回读 | 在未知状态下重复执行设备指令 |
| 浏览器页面错误 | 使用 Assist 备用页面、日志页或 PowerShell HTTP 检查 | API/终端健康检查、图表和原始 CSV | 用截图冒充刚完成的操作 |
| 设备状态未更新 | 运行 `reset_demo`；检查实体与故障注入开关 | 展示状态回读与失败恢复设计 | 只看服务返回就说成功 |
| 网络断开 | 保持本地 Docker/模型链路，展示内部健康检查 | `offline_network_test.json`、本地资料和能耗流程 | 临时接入云端以掩盖问题 |
| 模型输出非法 JSON | 展示 Schema 拦截；重试一次或使用已注册模板 | `SCHEMA_FAILURE_ANALYSIS.md` 与留存原文 | 直接手工修 JSON 后假装模型输出合法 |
| 性能过慢 | 预热模型、缩短上下文、演示简单快速路径 | 已准备的实测图表、录制片段 | 将 CPU 测试说成 GPU/NPU 加速 |
| 资料/能耗数据不可读 | 运行 `run_demo_tests`；检查受版本控制的资料和 CSV | 原始数据文件与测试结果 | 使用未说明的外部资料替代 |

## 现场最小恢复顺序

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\start_demo.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\healthcheck.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\reset_demo.ps1
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\run_demo_tests.ps1 -SmokeOnly
```

若四步后仍失败，停止实时设备操作，转为播放明确标识的同环境预录镜头，并展示 `assets/data/` 和 `reports/FINAL_EVIDENCE_AUDIT.md` 解释可复核结果与边界。
